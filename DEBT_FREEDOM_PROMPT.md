# Debt Freedom (plant debts): build prompt

Build the new **Debt Freedom** feature in DollarSeeds: a Debts tab where each debt is a plant growing out of a pot. The plant grows as the debt is paid off, using the debt snowball method (smallest balance first, and each paid-off debt's payment rolls into the next).

Read `CLAUDE.md` and every doc it points to before writing code. Follow its rules exactly, especially branching, the DB migration rules and gate, the API rules, i18n, and "never hardcode colors". Read `.claude/docs/architectural_patterns.md`, `data_model.md`, `design_system.md` and `i18n.md` in full.

## 0. Ground rules for this build

- **The existing debt system stays exactly as it is.** Debt goals (`savings_goals.goal_type = 'debt'`) on the Goals tab, their routes, their math and their UI must not change. Don't read from or write to `savings_goals` or `savings_transactions`. This feature is completely separate, with its own tables, routes and screens. We'll decide what happens to the old system once this one is proven.
- **Hide it behind a flag.** Add `DEBT_FREEDOM_ENABLED` in a new `frontend/constants/features.ts`, set to `__DEV__`. The Debts tab and every entry point render only when it's true, so production builds don't show it until I approve.
- **No new native dependencies.** Use what's already installed: `react-native-svg`, `react-native-svg-transformer`, `react-native-reanimated`, `react-native-gesture-handler`, `expo-haptics`. Rive comes later (see section 6). This means no dev-build rebuild is needed.
- **Keep the app light.** Only the plant that's settled on screen animates. Nothing loops while idle. See section 5.
- Work in small, reviewable commits.

### Routes

Add these under a new `/debt-freedom/` prefix in `backend/main.py`. Every route takes `user_id: str = Depends(get_current_user_id)` and filters on it. Add every route to the security test table so `test_every_protected_route_is_in_the_table` passes.

| Route | Purpose |
|---|---|
| `GET /debt-freedom/` | Full garden, with computed fields (below) |
| `POST /debt-freedom/` | Create a debt. Required: `name`, `original_balance`, `current_balance`, `min_payment`, `apr`. Optional: `debt_type`, `lender`, `due_day`, `pay_url`, `autopay`, `credit_limit`, `notes`. |
| `GET /debt-freedom/{id}` | One debt, plus its transaction history |
| `PATCH /debt-freedom/{id}` | Edit any field. Changing `current_balance` writes a `balance_edit` transaction. |
| `DELETE /debt-freedom/{id}` | Delete, cascading its transactions |
| `POST /debt-freedom/{id}/payments` | Body `{ minimum: bool, extra_amount?: number }`. `minimum` pays `min_payment`, and `extra_amount` is only accepted on the focus debt. Write one transaction per part, lower `current_balance` but not below 0, and lock the species on the first payment. |
| `POST /debt-freedom/{id}/complete` | Only allowed when `current_balance` is 0. Sets `status = 'paid_off'` and `paid_off_at`. |

### The rules

Put all of this in one pure-Python module, `backend/debt_freedom.py`, called by the routes. Unit-test it in `backend/tests/test_debt_freedom.py`.

**Order.** Paid-off debts come first, oldest `paid_off_at` first. Then active debts, by `current_balance` ascending, with ties broken by `created_at` then `id`. The **focus debt** is the first active one. `position` is 1-based, out of `total` (all debts).

**Species.** Let N be the total number of debts.

- If N < 4, every debt is species 4.
- Otherwise the debt at 0-based position i gets `floor(i * 4 / N) + 1`.
- Recalculate only for debts where `species_locked` is false (the ones still at the seed stage). Run the recalculation after every create, delete and balance change.

**Growth step.**

- `pct_paid = (original - current) / original`.
- Step 0 (seed) if there are no payments yet.
- Once there's a payment:
  - Step 1 if `pct_paid` < 10%.
  - Otherwise `min(10, floor(pct_paid * 10) + 1)`, so 10–19% is step 2 and 90–99% is step 10.
- `ready_to_complete` is true when `current_balance` is 0 and the status is still active.

**Rollover.**

- The focus debt's `suggested_payment` is its own `min_payment` plus the `min_payment` of every paid-off debt.
- Every other active debt's suggested payment is its own `min_payment`.

**Estimated payoff date.**

- Simulate month by month: add monthly interest (`balance * apr / 100 / 12`), apply the suggested payments, and when the focus debt reaches 0, roll its payment into the next debt.
- Return `est_payoff_month` for each debt (as YYYY-MM) and for the whole plan.
- Return null ("--" in the UI) if a payment doesn't exceed its interest, or after 600 months.

**Missed payment (my rule).**

- When a debt's due date passes and that billing cycle has no `payment_minimum`, add one month of interest at its APR as an `interest` transaction and raise `current_balance`.
- Run this lazily at the start of `GET /debt-freedom/` for each cycle since `interest_checked_through`, and only if `due_day` is set.
- Keep this in one function so the policy can change later.

**Computed fields per debt in GET responses:** `position`, `total`, `is_focus`, `growth_step`, `pct_paid`, `ready_to_complete`, `next_due_date`, `suggested_payment`, `est_payoff_month`, `paid_off_count_through_here` (used for the stream width), and a `missing` list naming any unset optional field the pot label shows (currently only `due_day`).

**Garden-level fields:** `plan_est_payoff_month` and `focus_id`.

## 3. Where it lives and what it looks like

### Files

- **New tab:** `frontend/app/(tabs)/debts.tsx`, registered in `(tabs)/_layout.tsx` after Goals (`piggyBank`). Add an icon to `TAB_ICONS` in `CustomTabBar.tsx`, drawn in the same style as the other tab icons. Label it `common:tabs.debts` in every locale.
- **Screens:** `frontend/app/debtDetail.tsx` (after-tap detail) and `frontend/app/debtForm.tsx` (create and edit), as Stack screens.
- **Components:** `frontend/components/debts/`, with `DebtGarden`, `PlantSection`, `PlantView`, `PotLabel`, `GardenHeader`, `WaterStream`, `FocusGlow`, `LogPaymentSheet`, `DebtCard`, and the animations.
- **API layer:** `frontend/lib/debtFreedom.ts`, with typed axios calls and the response types. The server computes everything; the client only renders.

### Visual style

- Use the "Seed & Soil" design system: every color from `useTheme()`, fonts from the `Fonts` export, and shadows from the `shadow()` helper.
- The plant art has its own fixed palette, since it's illustration and not UI. Everything around it uses theme tokens.
- **Missing values** show as `--` in `theme.danger`.
- **Focus glow:** a soft radial glow behind the focus plant, using Harvest yellow at low opacity with an SVG `RadialGradient`.

### Header

A fixed header at the top that describes the settled plant. It crossfades when a new plant settles.

- **Eyebrow**, in JetBrains Mono: "DEBT 3 OF 8".
- **Remaining balance**, large, in Instrument Serif: "$2,310 left".
- **Estimated payoff date:** "Free by Mar 2027".
- **Top right:**
  - a toggle between plant view and card view
  - a "+" button to add a debt

### Plant view

**Scrolling**

- A vertical `FlatList`.
- Each section is about 82% of the available height, so the top of the next pot peeks in at the bottom.
- `snapToInterval` set to the section height, plus `decelerationRate="fast"` and `getItemLayout`.
- `initialScrollIndex` set to the focus debt, so the page opens on it.
- Older (paid-off) debts are above and newer ones below: swipe down for older, swipe up for newer.

**Each section**

- The plant canvas is scaled to the width minus a 16px gutter on each side, keeping the 4:5 aspect ratio.
- Show `frame-<growth_step>`, the paid-off art, or the seed, depending on the debt's state.
- **`PotLabel`** is React Native text laid over the `pot_label` rectangle, so the text stays sharp and accessible:
  - line 1: debt name
  - line 2: "$150 min · due Oct 14"
  - line 3: "50% paid"
  - a missing due date shows as `--` in red
  - use Geist, and scale the text so the longest name fits

**Water stream (`WaterStream`)**

- Shown between a paid-off plant and the next plant below it.
- An `react-native-svg` path starting from the ground under the paid-off plant.
- Fully visible for the first ~60% of the gap, then a linear-gradient fade to 0%. It must be fully clear a fixed distance above the next section's top edge, never touching the next plant.
- Its width grows with `paid_off_count_through_here`, capped at 40% of the pot width.
- Static after its first animation.

**Tapping**

- Tapping a plant or its pot opens `debtDetail`.
- The settled focus debt also shows a "Log a payment" button below its pot.
- A debt with `ready_to_complete` shows a "Mark as paid off" button instead.

### Card view

A plain `FlatList` of `DebtCard`s, using the existing `Card.tsx`, in the same order and showing the same pot-label info. Tapping a card opens `debtDetail`.

### Empty state

A single pot with a seed and a "Plant your first debt" button that opens `debtForm`.

### Detail screen (after tap)

A regular card-style screen with Edit, Log payment and Delete (with a confirmation). It shows:

- type
- lender and pay link (opens with `expo-web-browser`)
- original balance and start date
- interest rate
- minimum payment and the suggested payment including rollover
- due day and autopay
- monthly interest and interest remaining (from the simulation)
- credit limit and usage (credit cards only)
- payment history
- notes
- which debt it rolls into next
- one short encouraging verse, chosen at random from a small list in the locale files (for example Proverbs 22:7 or Romans 13:8)

## 4. Creating a debt

1. The "+" button (or the empty-state button) opens `debtForm` in create mode.
2. **Required fields:** name, original balance (hint: "if you're not sure, use today's balance"), current balance, minimum payment, interest rate (%).
3. **Optional fields,** under a "More details" section collapsed by default: type, lender, due day of the month, pay link, autopay, credit limit, notes. A skipped due day shows as red `--` on the pot label.
4. Use the existing `InputField`, `Dropdown` and `Button` primitives. Validate all five required fields before submitting.
5. On save, POST, return to the garden, scroll to the new debt's section, and play the seed-planting animation (the seed drops into the soil). This plays once, only on creation.
6. Edit mode uses the same form with the values filled in.
7. **Logging a payment (`LogPaymentSheet`):**
   - A bottom sheet with a checkbox, "Paid minimum ($150)".
   - On the focus debt only, an optional extra amount field.
   - On success: a light haptic, the drops animation (3–4 drops for minimum only, more plus a splash with extra), then a grow transition if the step changed.
8. **Completing a debt:** tapping "Mark as paid off" calls `/complete`, then plays this sequence (tap to skip):
   1. roots expand
   2. the pot fragments fall with gravity and settle on the ground
   3. a 3-second glare on the plant
   4. the stake appears with "Paid off · <Mon YYYY>"
   5. the water stream flows down and fades
   6. the list scrolls to the new focus debt
   The fragments and stake stay afterward, as the paid-off art.
9. **The bug (flytrap species only):**
   - It can appear at most once per session: a 20% chance when a flytrap is the settled plant.
   - It always appears right after a payment is logged on a flytrap.
   - Animate it through the catch poses a–d, then stop. Never loop.

Log analytics events through `lib/analytics.ts`: `debt_created`, `debt_payment_logged`, `debt_paid_off`.

## 5. Performance and accessibility

- Only the settled section animates. Use `onViewableItemsChanged` with a 60% threshold.
- Neighboring sections render their static frame, and anything further away isn't mounted (`windowSize` about 3, memoized items, stable callbacks).
- Pause everything when the tab isn't focused (`useIsFocused`) or the app is in the background (`AppState`).
- Animations use Reanimated on the UI thread, animating only transform and opacity.
- Respect Reduce Motion (`useReducedMotion`): skip straight to end states.
- Accessibility label for each plant, for example "Chase Visa, 50% paid, step 6 of 10, debt 3 of 8".
- Test with 0, 1, 3, 4, 8 and 15 debts.
