# Localization (i18n)

Two **independent** display settings, both device-local (`AsyncStorage`, no backend, no
API change):

| Setting | Key | Values | Effect |
|---|---|---|---|
| Language | `display_language` | `en`, `pt-BR` | Words **and** number separators |
| Currency | `display_currency` | `USD`, `BRL` | **Symbol only** — never converts a value |

All four combinations are valid; neither setting constrains the other.

| Path | Purpose |
|---|---|
| [frontend/lib/i18n.ts](../../frontend/lib/i18n.ts) | i18next init. Read the comments before changing options. |
| [frontend/context/LocaleContext.tsx](../../frontend/context/LocaleContext.tsx) | State, persistence, and every **bound** formatter |
| [frontend/locales/`<lang>`/](../../frontend/locales/) | 11 namespaces per language; `en` is canonical |
| [frontend/lib/serverStrings.ts](../../frontend/lib/serverStrings.ts) | Maps English the **backend** composed → display label |
| [frontend/constants/txCategories.ts](../../frontend/constants/txCategories.ts) | Canonical `SOURCES` / `SUBCATS` (stored values) |
| [frontend/constants/months.ts](../../frontend/constants/months.ts) | Canonical `MONTHS` (stored + ordering key) |

Adding a language = add `locales/<tag>/`, add the tag to `SUPPORTED_LANGUAGES`. No screen
changes.

---

## The invariant

> **Canonical English values stay on the wire and in the database, forever. Translation
> happens only at render, keyed by the canonical value.**

Covers month names, categories (`Needs`/`Wants`/`Goals`), income `source`, expense
`sub_category`, `budget_type`, `goal_type`, and savings `type`/`source`.

A picker whose *value* becomes the translated label writes `"Agosto"` rows that no
`.eq("month", …)` matches — and the failure is **silent**: [main.py:692](../../backend/main.py:692)
returns `{"data": []}` for an unknown month rather than erroring.

Three literals are deliberately English and marked `// i18n-canonical`, which is also
how the checker skips them:

| Location | Literal | Why |
|---|---|---|
| [piggyBank.tsx:371](<../../frontend/app/(tabs)/piggyBank.tsx:371>) | `'Savings goal'` | Written to `savings_transactions.title` |
| [settings.tsx:548](../../frontend/app/settings.tsx:548) | `"DELETE"` | Backend matches this exact string |
| [_layout.tsx](<../../frontend/app/(tabs)/_layout.tsx>) | Tab `title`s | Not the tab labels — `CustomTabBar` translates those from `common:tabs` |

## Checks — run both before merging any locale change

```bash
cd frontend
npm run check-locales   # key + placeholder parity, hardcoded values, unreferenced keys
npm run verify-i18n     # boots real i18next: plurals, pt-BR resolution, fall-through
```

They are complements, and each caught a live bug the other structurally could not see.
`check-locales` reads files; `verify-i18n` boots i18next, which is the only way to catch
a key that exists under a name i18next never asks for — as happened when plurals were
written `_one`/`_other` while `compatibilityJSON: 'v3'` looks up `_plural`.

## NOT translated — deliberate, and staying that way for the next update

The owner has decided this scope is final for the coming release. **Everything below is a
known gap, not an oversight. Do not "fix" any of it without asking.**

### 1. Server-supplied video-series content

Series `title`, `description`, `creator`, and each lesson's `title` / `description` come
from Supabase ([main.py:1699](../../backend/main.py:1699), [:1740](../../backend/main.py:1740)) and are
authored in English.

**Consequence, accepted:** the Lessons tab is bilingual — Portuguese chrome around English
series content. There is no "available in English" affordance; it is simply English.

Translating this later means a schema change (per-language columns or a translations
table), so it is an expand→contract migration, not a frontend edit.

### 2. `TERMS_URL` / `PRIVACY_URL`

English-only pages, linked from the **Portuguese** paywall and Settings.
See the `TODO(i18n)` in [frontend/constants/legal.ts](../../frontend/constants/legal.ts). The
disclaimer text itself *is* translated (`common:legal.*`); only the linked pages are not.

This is the gap most worth closing before promoting pt-BR in the Brazilian App Store
listing — Apple has rejected apps for policy links a user cannot read.

### 3. App Store / Play Store listing

Description, keywords, screenshots and the What's New text are English only. Store
metadata lives in App Store Connect, not this repo.

### 4. `app/modal.tsx`

Untouched `create-expo-app` boilerplate ("This is a modal" / "Go to home screen").
Registered in [app/_layout.tsx:102](../../frontend/app/_layout.tsx:102) but **nothing navigates
to it** — no `/modal` route push exists anywhere in `app/` or `components/`. Left as-is
because translating dead boilerplate would imply it is a real screen.

### 5. Device QA of pt-BR layout

Portuguese runs 20–30% longer and **73 short labels grow more than 25%**. Two known
overflows were fixed by shrink-to-fit (the 50/30/20 preview, the expense category cards)
and two by shortening the label (`depositForm.plantSeed`, `editGoal.save` — both share a
half-width button with an icon). The rest is measured, not seen.

Not a translation task, but the reason "translated" ≠ "verified".

## If you do pick any of this up later

Remove the corresponding note here in the same commit. A stale entry in a "deliberately
skipped" list is worse than no list — it tells the next reader a decision still stands
when it does not. The same failure already happened once to `check-locales`' own
exemption list, where `constants/lessons.ts` stayed exempt after its prose was translated,
silently disabling the check for that whole file.
